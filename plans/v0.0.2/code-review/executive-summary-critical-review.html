What the score means

5 to 6 means mixed design with useful seams and clear debt. The code ships and reads well in parts. The central types carry too much state. Fix order is correctness first, then surface, then speed with numbers.

Good and bad

Good, keep it

No import cycles. Four direct deps, each used. Modern ServeMux with timeouts. Narrow host optionals. Error chains use percent w. Traversal checks exist. No nolint. No exit in library code.

Bad, fix in order

Mask layer index has no empty check at internal/masking/mask_apply.go:19. Decode and bake run under global locks. Page holds about 50 fields. Screen has 27 methods. Aliases repeat one thing under many names. Sentinels use three styles. Window stores a context. Serve drops cancel.

Critic view

I rate this a 6.4 because the base is sound and the debt is known. The lock items and the mask guard are real production work. The alias and Screen items are real but slow. The pool and micro alloc items are theory until a profile says otherwise.

I push back on deleting internal/ipc for lack of internal callers. It is public API. I push back on deleting three packages on import graph alone. Check outside callers and write a release note first.
